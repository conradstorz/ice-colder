# Ledger (`ice_edge.ledger`)

Scoped `CLAUDE.md`, loaded when working under `packages/edge/src/ice_edge/ledger/`. Moved from the root `CLAUDE.md`; project-wide rules stay there.

**FIFO method attribution:** `escrow_credits` is a FIFO ledger of `Credit(method, cents, ts)` that backs `credit_escrow_cents`, which remains the authoritative total (integer cents; see Money below). Deducting a sale's price consumes credits first-in-first-out (`EscrowLedger.consume_fifo`) and records the per-method shares on `pending_sale_shares`; `vend_failed` restores **exactly those shares as separate credits with their original methods**, so money is never reclassified when a sale fails. Method strings are stored raw from `PaymentEvent.method` and classified only at query time. If the ledger and the total ever disagree the sale is booked to `{"unknown": price}` with a warning — a bug guard, not a path. The ledger itself lives in `packages/edge/src/ice_edge/ledger/escrow_ledger.py`'s `EscrowLedger` (the second piece carved off the VMC god object, after `FaultRegistry`); `credit_escrow_cents`/`escrow_credits` stay public read/write conveniences on the VMC over the ledger's `total`/`credits` (the divergence guard inside `EscrowLedger.consume_fifo` still only ever sees them move together), and `escrow` is the public read-only `@property` over the `EscrowLedger` object itself for callers that want it (e.g. `vmc.escrow.is_empty_within_tolerance`).

**Session recovery extraction:** the PAY-104 read-and-decide half of crash recovery lives in `packages/edge/src/ice_edge/ledger/session_recovery.py`'s `SessionRecovery` (carved off the VMC god object after `FaultRegistry` and `EscrowLedger`), owned by `Machine`, not the VMC. It owns the boot-time three-way decision over a loaded snapshot (`evaluate_at_boot()` returns a `BootDecision` of `discard_test`/`uncertain`/`closed`/`none`, performing `SessionStore.clear()` itself for the two discard cases) plus the read-only `pending_sale_for_recovery()` accessor and its record-once guards (`_pay104_sale_key`, `pending_sale_already_recorded`, `reserve_pending_sale`, `mark_pending_sale_recorded`) — `_recorded_pay104_keys` is this class's own state, lost on restart by design. The VMC keeps only snapshot building (`_snapshot`/`snapshot()`); `Machine.set_session_store` runs the boot evaluation and its own side effects (`_flag_uncertain_session` on `uncertain`; the warning log on `discard_test`), and the four public recovery methods (`pending_sale_for_recovery`, `pending_sale_already_recorded`, `reserve_pending_sale`, `mark_pending_sale_recorded`) are one-line forwards on `Machine` that routes and 20+ tests call as `machine.<method>()`, not `vmc.<method>()`. The `is_test` chokepoints described above live in `SessionRecovery.evaluate_at_boot` and `SessionRecovery.pending_sale_for_recovery`; the guarantee is unchanged. `SessionRecovery` also takes an injected `sale_recorded(sku, since_ts, methods, window_seconds)` (wired by `Machine` to `EventRecorder.sale_recorded_since`, so the recorder must be attached before the session store): an `uncertain` snapshot whose sale already has a `sales` row (crash after the live insert, before the idle snapshot clear) is cleared as `closed` at boot with no PAY-104 only when the snapshot also holds no leftover credit (`credit_escrow_cents == 0`, exact), no pending payout (`pending_payouts`) and no read error (otherwise PAY-104 is still raised for the operator); the row match is `since_ts <= ts <= since_ts + window_seconds` with no slack, where the window is `dispense_timeout_seconds + SALE_MATCH_MARGIN_SECONDS` (margin 480 s, so 600 s at the default 120 s timeout; `Machine` supplies it as a callable so an edited timeout is honoured), and `pending_sale_for_recovery` returns `None` whenever the row exists, so the "Record as sale" card is never offered for it. `SessionRecovery.recovery_detail()` (forwarded as `Machine.recovery_detail()`) is a pure read of that snapshot that `health_faults.html` renders as chips on the PAY-104 row (sale already recorded, leftover credit, unconfirmed payout or cash sale, snapshot error; nothing when the field is absent, as on the cloud); there is deliberately no "Refund leftover" action: after a restart the credit is no longer in edge escrow, and once PAY-104 resolves the edge-start reconciliation pays the board's excess out as an `error` payout (spec §5.5). The match window is `dispense_timeout_seconds + SALE_MATCH_MARGIN_SECONDS` (480 s; 600 s at the default), passed to `EventRecorder.sale_recorded_since(..., window_seconds=)`.
