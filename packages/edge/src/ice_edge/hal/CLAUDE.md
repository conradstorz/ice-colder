# HAL (`ice_edge.hal`)

Scoped `CLAUDE.md`, loaded when working under `packages/edge/src/ice_edge/hal/`. Moved from the root `CLAUDE.md`; project-wide rules stay there.

**Telemetry router extraction:** every inbound MQTT handler that only reads/validates its payload lives in `packages/edge/src/ice_edge/hal/mqtt_inbound.py`'s `TelemetryRouter` (carved off the VMC god object), owned by `Machine`, and is now a pure fan-out: it validates, logs and publishes the decoded values to six typed `ice_common.observers.Subscribers` lists (`subscribe_hardware_io`, `subscribe_sensor`, `subscribe_heartbeat`, `subscribe_ice_maker_event`, `subscribe_telemetry`, `subscribe_capabilities`; each returns an unsubscribe callable) and holds no health/availability/gate/fault reference. An invalid payload reaches no subscriber; `handle_command_ack` only logs. The public `capabilities` dict is the raw-document store (`Machine.subsystem_capabilities` returns that same object), and `subscribe_capabilities` replays every stored document to a new subscriber because `capabilities/+` is retained. `Machine` does all wiring: `HealthTelemetry` (`ice_edge.monitoring.health_telemetry`, the payload-to-`HealthMonitor` calls) on all six, `IcePolicy` (`ice_edge.faults.ice_policy`, the bin-sensor ICE-101 clear via `VendingChannel.bin_half_full`) and `Availability.set_hardware_io` (re-subscribed by `set_availability`) on the relevant list (payment state arrives through `StateConsumer`, not the router), and `DispenserProfileGate.on_vending_capabilities` on capabilities (it ignores `caps is None`). The `sensors/water_flow` topic is gone. Names that arrive in payloads or topics (subsystem, sensor location, hardware/payment device, telemetry channel id) must match `CHANNEL_ID_PATTERN` or the message is dropped with one warning per distinct bad name; the `capabilities` store and the `HealthMonitor` dicts are capped (`MAX_SUBSYSTEMS` 32 in `ice_contracts.board.common`, `MAX_TEMPERATURE_KEYS` 64, `MAX_CHANNEL_KEYS` 256, `MAX_SIGNALS_PER_SUBSYSTEM` 256 in `health_monitor.py`), a new key past a cap being dropped with a warning while existing keys keep updating.
