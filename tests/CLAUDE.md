# Tests

Scoped `CLAUDE.md`, loaded when working under `tests/`. Moved from the root `CLAUDE.md`; project-wide rules stay there.

**Browser tests:** `tests/edge/web/test_dashboard_v2_home_browser.py`, `tests/edge/web/test_dashboard_v2_boosted_nav_browser.py`, `tests/edge/web/test_users_codes_pin_browser.py` and `tests/edge/web/test_touch_feedback_browser.py` drive real headless Chrome via `tests/browser/*.mjs` checker scripts (Node standard library only). They're skipped unless `ICE_COLDER_BROWSER_TESTS=1` is set **and** a Chrome/Chromium binary (honoring `CHROME_PATH` first) plus a `node` executable are both found, so a machine without Chrome still runs the rest of the suite clean. CI sets the flag and installs a pinned Chrome and Node so these five (the four above plus `tests/cloud/test_badge_boosted_browser.py`, which checks the cloud context badge never stacks on boosted navigation and the old remote banner is gone) run on every push/PR; a guard step in `ci.yml` fails the build if any of them skip instead of passing.

**Public surface:** tests and routes reach the VMC only through its public surface, never an underscore attribute. Read-only: `faults` (the `FaultService`), `escrow` (`EscrowLedger`), `outputs` (`StatusOutputs`), `sale` (a `SaleContext`, `packages/edge/src/ice_edge/sale/sale_context.py`, `None` when no sale is in flight; `selected_product` is a read/write property and `pending_sale_shares` a read-only property, both over `sale`), `credit_escrow_cents`/`escrow_credits` (read/write conveniences over `escrow`), `test_sale_in_progress`, `state` (a plain attribute; mutate only through a trigger or `set_state`), `products`, and the public instance attributes `session_timeout_seconds`/`dispense_timeout_seconds`. `select_product(product)` takes a `Product`, not an index: `on_button_press` validates the `ButtonPress` (its `button` is a named channel id such as `button_ice`, not a number), resolves it through `product_for_button(products, button)` against `Product.button`, and refuses an unknown button via the journal before calling it. `select_product` refuses a sold-out product before it is selected, and `process_payment` re-runs the refusal and stock checks before consuming escrow. The event port: the sale-driving inbound handlers (`on_button_press`, `on_dispenser_event`) and the three the MDB gateway calls back into (`deposit_funds(cents, method, event_id=...)`, `on_payment_lever`, `on_payout_paid`), the two callbacks a `DispenseCycle` invokes (`on_dispense_failed`, `note_dispense_request`), `process_payment()`, and `raise_fault`/`clear_fault` (one-line forwards onto `FaultService`, kept because the FSM is a legitimate raiser). The test-sale seams: `begin_test_sale(product) -> bool`/`end_test_sale()`/`find_product(sku)`, and `make_idle_for_service()` -- the one FSM operation `MaintenanceLease.begin_standby` cannot do for itself. The observer hooks `TestSaleRunner` uses: `subscribe_state_change`/`subscribe_sale_settled`. `snapshot()`, `cancel_timers()`, `get_status()`, and `active_faults()` round it out. Everything else -- the ten `set_*` service attachments, `attach_to_loop`, `cancel_pending_tasks`, `drain_persistence`, the service properties (`session_store`, `mqtt_client`, `command_dispatcher`, `health_monitor`, `availability`, `event_recorder`, `display_controller`, `subsystem_capabilities`), `recovery`, `telemetry`, `lease`, `gate`, `tasks`, `test_sales`, `maintenance_hold`, the four PAY-104 recovery forwards, the QR-cycling body of `initiate_virtual_payment` (moved to `PaymentGatewayManager.next_payment_prompt`), and `run_test_sale` itself -- lives on `Machine` or its collaborators, below. The rule is otherwise unchanged: tests and routes may **read** a collaborator directly (`vmc.faults.is_locked(sku)`, `vmc.sale.is_test`, `machine.gate.profiles`, `machine.lease.hold`, ...) but **mutate** only through a VMC/Machine method -- never by poking a collaborator or a `vmc._<name>`/`machine._<name>` attribute. Time is under the same discipline: `tests/fakes.py`'s `FakeTaskRunner` stands in for the real `TaskRunner`; the `machine`/`vmc` fixtures build a `Machine`/its `.vmc` with a real one, and `machine_fake_time`/`vmc_fake_time` build them on a `FakeTaskRunner` attached to the running loop instead, yielding `(machine, runner)`/`(vmc, runner)`; every timer the VMC or a collaborator arms carries one of eleven labels -- `dispense_timeout`, `session_timeout`, `process_payment`, `maintenance_idle`, `standby_sweep`, `ice_retry_cooldown`, `ro_overrun`, `payout_retry`, `policy_retry`, `policy_verify`, `mdb_keepalive` -- so a test fires it by label (`runner.fire("dispense_timeout")`) rather than reaching for the scheduled task itself. The same discipline extends to non-timer waits: `tests/fakes.py`'s `settle(turns=3)` yields to the loop a bounded number of times so a fire-and-forget task with no real I/O finishes, `FakeTaskRunner.drain_persistence()` awaits persistent tasks the same way the real `TaskRunner`'s does, and the simulator command loop's `queue.join()` (now that `command_loop` calls `queue.task_done()` in a `finally`) lets a test await every queued command's processing instead of sleeping past it. Tests never wait on the wall clock for synchronization -- the two sanctioned exceptions are a never-completing stand-in (`sleep(10|100|3600)`, meant to be cancelled or simply never reached before the test asserts) and a bounded poll interval checked in a loop. `asyncio.sleep(0)` remains common throughout (it yields one event-loop turn rather than waiting on the clock at all), and a documented, deliberate residual fixed sleep or two still survive where no public observable exists to poll instead (e.g. `tests/integration/test_integration_e2e.py`'s "Deliberate residual fixed sleep" comment).

`tests/meta/test_no_private_access.py` enforces the no-private-access rule across the whole suite as a per-file budget ratchet, not a hardcoded `vmc`/`machine` special case: `tests/private_access_budget.py`'s `BUDGET` dict caps how many private attribute accesses -- found by walking each file's `ast`: any `Attribute` node whose name is `_[a-z]...` on anything but bare `self`/`cls` (so `f()._x`, `xs[0]._x` and `(a or b)._x` count), plus `getattr`/`setattr`/`hasattr`/`delattr` calls whose second argument is a `"_x"` string; dunder access like `vmc.__class__` is excluded -- plus private `from m import _x` imports each `tests/**/*.py` file may have, and a file not listed has an implicit budget of 0. The test fails over budget, listing every offending `path:line`, and fails under budget too ("lower BUDGET[...] to N") -- budgets only ever move down, never up. **To lower one:** fix the tests until the count drops (promote the private name to a public seam, or stop reaching past one), run `uv run python tests/meta/test_no_private_access.py` to print the current counts, then edit that one number in `tests/private_access_budget.py`. A `# private: <reason>` marker (the reason must be non-empty; a bare `# private:` exempts nothing) on one of the three lines above a hit exempts that hit entirely (not the hit's own line -- the lookback window ends just before it) -- the escape hatch for a test that must reach a private to drive an otherwise-unreachable defensive branch. Because it parses code rather than matching text, a comment, docstring or string literal mentioning `obj._name` is never a hit (unlike `test_static_css.py`'s regex class extractor, Key Patterns below).

`tests/route_context.py` gives the test suite one place to snapshot and restore every mutable `ice_edge.web.context` global, instead of each test hand-rolling its own `routes.set_X(None)` teardown. `GLOBALS` names all 13 of them; `snapshot()`/`restore()` save and put values back via plain `setattr`, then resync `ice_edge.web.auth`'s own access-store reference, reset the login back-off, and clear its trusted-proxy list (`web_auth` keeps state `context`'s globals don't reach); `discoverable_globals()` walks `vars(context)` for every non-dunder, non-callable, non-module/class, non-ALL_CAPS name, so adding a 14th global to `context.py` without adding it to `GLOBALS` fails `tests/edge/web/test_route_context.py`'s `test_globals_covers_every_module_global` guard. `tests/conftest.py`'s autouse `_isolated_route_context` fixture snapshots before every test and restores after, so the old hand-rolled teardowns are gone; a `set_X(None)` call that remains in a test is a pre-action setup asserting behaviour with that dependency absent, never cleanup.
